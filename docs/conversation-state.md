# Conversation state and recovery

Each ordinary room has a `room:<room ID>` state; each logical DM has a `dm:<peer signing public key>` state. A DM is still delivered through the recipient Inbox. No additional DM transport or per-contact Waku connection is created.

State contains the optional history start time (null means all available history), signed-message reading anchor (ID, sender, timestamp, viewport offset), bounded seen-message IDs, hidden message IDs, blocked signing keys, and signed channel catalog. History uses stable timestamp/sender/ID ordering; restoration prefers the exact message and then the closest available successor. Older messages remain authenticated without applying the live replay window. Node retention still determines availability.

State is encrypted locally with an identity-derived key. Persistent identities also encrypt it using the Archive master key in `uk.wakukusmartrecipe.soft.conversation` records with random record IDs. Filtering and reading state have independent authenticated update times so syncing reading progress does not overwrite newer filtering rules. Offline local records are republished during subsequent synchronization.

A background queue reuses the Inbox node for serial Store checks, with a 20-second scheduling interval, one page per source and a 12-second cancellation budget. The active conversation is deferred. One Inbox check covers every logical DM. Hidden applications and foreground history loads suspend scans. Opening a conversation loads all available authenticated history, with no seven-day or 1,000-message client truncation. Search is local to loaded messages and channel catalogs.

Archive is directly under Identity as Manage Archive. Private keys and recovery secrets are never rendered. Filters and display name are editable. Recovery reset also appears under the collapsed Recovery options on the login form. Both require confirmation. Rotation wraps the same Archive key in a fresh recovery secret and conditionally replaces the PDS recovery record, preserving the Waku identity and all encrypted records. The new file remains downloadable if the remote update succeeds but local cache writing fails. An old file cannot unwrap the current PDS recovery record, but previously downloaded old wrapping records, backups and decrypted data cannot be revoked. Existing devices with the Archive key keep working.

Validation: unit tests cover encryption, independent field merge, offline retry, stale message authentication, queue order and reading anchors. `browser-conversations.mjs` uses the real UI with deterministic transport fixtures for unordered pagination, restoration, search, moderation and queue badges. `browser-persistent-recovery.mjs` exercises encrypted PDS records and both reset paths with a mocked PDS. Real Waku DM regression remains separate in `browser-dm.mjs`.

Message removal is a reversible local/Archive visibility rule, exposed through touch long-press, desktop right-click or Shift+F10. Explicit rule edits advance a monotonic timestamp. Conversation persistence and synchronization share a serial queue so an in-flight older sync cannot write back a removed hidden-message ID.

Identity preferences offer Light, Dark and System across all three skins; the device preference survives login and app restarts. Walkie-talkie pages use a separate black background and high-contrast press-to-talk control. A profile shows its public signing identity, with account identifiers and private Archive counts shown only in the owner's in-app preview. Those counts and account metadata are not embedded in share links.
